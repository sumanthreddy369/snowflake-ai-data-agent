User is building a two-project portfolio series called "AI Data Agent Projects" comparing Snowflake and Databricks as the backing stack for a natural-language data agent.

**Project 1: Snowflake (DA-weighted)** pipeline stages:
1. Ingest — Snowpipe (raw data flows in automatically)
2. Bronze — raw Snowflake tables, untouched
3. Silver — clean/dedupe/standardize via Streams + Tasks
4. Gold — business-ready star schema via dbt
5. Semantic Layer — Cortex Analyst YAML defines business terms (e.g. "revenue", "active user")
6. Agent — Cortex Analyst answers plain-English questions
7. Governance — RBAC + data masking controls access
8. Validate — manual SQL comparison checks the agent's answers

**Why:** The stated goal is to demonstrate the ability to make messy data understandable and *accurate* for an AI agent to query — i.e. a portfolio proof point about data quality/semantic-layer design, not just pipeline plumbing.

**Domain history:** retail → bank card transactions (2026-09-21, rejected as insufficiently "real" — real bank transaction feeds are never public even at scale) → **real-time U.S. equities market data (current, as of 2026-09-22)**: trades + minute bars (OHLCV) + a symbol reference table, sourced from Alpaca's free IEX websocket feed. Chosen because it's genuinely real (not synthetic), raises the technical bar (market hours/timezones/corporate actions/true streaming volume), and stays in a recognizable finance vertical. User explicitly confirmed keeping **healthcare for the companion Databricks project** (built in a separate session/tab — this session/repo is Snowflake-only) rather than switching it to finance too.

**Current architecture (2026-09-22):** DB name `MARKET_AGENT`. Bronze/Silver: `TRADES`, `BARS`, `SYMBOLS`. Gold (dbt): `dim_symbols`, `dim_date`, `fct_trades`, `fct_bars` (the latter computes `rolling_volatility_30` via a window function — trailing 30-bar stddev of returns). Semantic layer measures: `total_volume`, `vwap`, `period_return` (last close vs first open, not an average of per-bar returns), `volatility`. **Governance pivoted from PII masking to a Row Access Policy** modeling real market-data licensing: non-`REALTIME_DESK` roles (including `ANALYST_AGENT`, which Cortex Analyst runs as) only see rows ≥15 minutes old — mirrors real delayed-quote entitlements. Real-time ingestion: `streaming/alpaca_stream_producer.py` (live, needs `ALPACA_API_KEY`/`SECRET`) or `streaming/generate_sample_data.py` + `replay_sample_data.py` (offline fallback, ~10k-row random-walk sample committed to the repo) → Kafka topics `market-trades`/`market-bars` → Snowflake Kafka Connector in Snowpipe Streaming mode.
